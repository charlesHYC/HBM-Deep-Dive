2 DRAM Cell 儲存原理

電容式存儲（DRAM Cell = 1T1C）

每個 DRAM cell 由一個電晶體（Transistor）+ 一個電容（Capacitor）構成，簡稱 1T1C。

  • 邏輯 1 = 電容充飽電（高電壓）
  • 邏輯 0 = 電容放電（低電壓）
  • 電容非常小，電荷會隨時間自然洩漏——這就是為什麼 DRAM 需要定期 Refresh
  一個 DRAM Cell：

       Word Line（字元線，由 Row Address 決定開/關）
           │
           ▼
      ─────╥─────
           │     ← 電晶體（Gate 受 Word Line 控制）
           │
      ─────┼─────── Bit Line（位元線）
           │
           ╞═══╡   ← 電容（儲存電荷）
           │
          GND

  Word Line = HIGH → 電晶體導通 → 電容與 Bit Line 連通
  Word Line = LOW  → 電晶體截止 → 電容與 Bit Line 斷開（保存資料）

破壞性讀取（Destructive Read）

這是 DRAM 最核心的物理特性，所有 ACT/PRE 行為都因此而存在。

  讀取前：Bit Line 預充到 Vdd/2（中間電壓）

  ACT 觸發，Word Line 拉高：

    電容（儲存 1）: 電荷 >> Vdd/2 → Bit Line 往上偏  (+ΔV)
    電容（儲存 0）: 無電荷 << Vdd/2 → Bit Line 往下偏 (-ΔV)

    ΔV 非常小（只有幾 mV）！

  Sense Amplifier 偵測到 ±ΔV 並強制放大：
    +ΔV → Bit Line 打到 Vdd（= 邏輯 1）
    -ΔV → Bit Line 打到 GND（= 邏輯 0）

  ⚠️  放大過程中，電容的原始電荷已經被拉走或注入
       電容裡的值 = 已損壞（unstable）

  Sense Amplifier 放大完後：
    → 自動把正確值「寫回」電容（Restore）
    → 電容重新充/放電到 Vdd 或 GND

  所以讀取 = 放大 + 寫回，是一個破壞-恢復的過程！
為什麼需要 PRE（Precharge）
讀完之後，Bit Line 停在 Vdd 或 GND，不是 Vdd/2。下次 ACT 不同 Row 之前，必須先把 Bit Line 重新充電回 Vdd/2（中間電壓），否則 Sense Amplifier 無法感測微小差異。這個「重置 Bit Line 到 Vdd/2」的動作就是 PRE（Precharge）。PRE 也讓 Row Buffer 回到 idle 狀態（沒有 row open），等待下一個 ACT。

「Bank 歸0」的正確解讀：Bank 回到預充電（precharged）/ idle 狀態，代表這個 bank 沒有 row 是 open 的，可以接受下一個 ACT。不是指資料被清空為 0。

Row Buffer 在哪裡

Row Buffer 在 DRAM Die 內部，緊鄰 Cell Array，不在外部（不在 Base Die、不在 FPGA）。

       │ Bank2: [SA][SA]...[SA]  ← Row Buffer C （open: Row 100）

       │ Bank0: [SA][SA]...[SA]  ← 各自獨立
       │ Bank1: [SA][SA]...[SA]
       │ Bank2: [SA][SA]...[SA]

  條件：同一個 bank 的 row buffer 同時只能 open 1 個 row
        不同 bank 之間完全獨立，互不影響

4 ACT / CAS / PRE 存取時序

ACT（Activate，激活）

術語：ACT = Activate，激活。告訴 DRAM「打開這個 Row 的 Word Line，把整行資料複製到 Row Buffer」。

動作發生什麼
MC 發出 ACT 指令帶有 Row Address（RA[13:0]）
Word Line 拉高該 Row 上所有 cell 的電晶體同時導通（一個 Row = 1 KB = 8192 個 cell）
電容接通 Bit Line電荷讓 Bit Line 從 Vdd/2 偏移 ±ΔV
Sense Amplifier 啟動偵測微小 ΔV 並放大到 Vdd / GND
電荷寫回電容同時進行，修復破壞性讀取的損壞
等待 tRCDRD≈ 13 AXI CLK，SA 放大完成才能 CAS
Sense Amp 啟動時機
ACT 時就開始了，不是 CAS 才開始。CAS 的時候 Sense Amplifier 早就做完感測，Row Buffer 已鎖定好每個 column 的值（1=Vdd, 0=GND）。CAS 只是從已感測完的 Row Buffer 中選出你要的那個 column。

CAS（Column Address Strobe，讀欄）

術語：CAS = Column Address Strobe。告訴 DRAM「從現在 open 的 Row Buffer 裡，給我第 N 個 column 的資料」。

動作發生什麼
MC 發出 READ 指令帶有 Column Address（CA[4:0]）
Column Mux 選通從已感測完成的整個 Row Buffer 中，選出指定 column 對應的 32 bytes
資料輸出32 bytes 透過 TSV → Base Die → FPGA AXI RDATA
Row Buffer 保持 open同 Row 下一次 CAS 不需要再 ACT

同一個 Row 的連續 CAS（不換 row）：每次只需 CAS Latency ≈ 2 CLK（pipeline 模式）。

PRE（Precharge，預充電）

術語：PRE = Precharge，預充電。強制關閉目前 open 的 Row，把 Bit Line 充回 Vdd/2，讓 bank 回到 idle 狀態。

動作發生什麼
MC 發出 PRE 指令或由 Auto-Precharge 自動觸發（存取時設定 AP bit）
Word Line 拉低電晶體截止，電容與 Bit Line 斷開
Bit Line 充電到 Vdd/2Precharge 電路把 Bit Line 帶到中間電壓
等待 tRP≈ 13 AXI CLK，充電完成才能 ACT 下一個 Row
Bank 回到 idle可以接受新的 ACT 指令（「Bank 歸0」= 這個意思）
為什麼讀完要 PRE
即使你只是「讀取」，DRAM 電容的電荷在 ACT 時已被破壞（被拉走）。Sense Amplifier 會自動把值寫回電容（Restore），所以資料不會消失。但 Bit Line 停在 Vdd 或 GND，不是 Vdd/2，必須 PRE 才能讓下次 ACT 的 Sense Amplifier 正常工作。

Write（寫入）行為

寫入時，如果 Row 已經 open（Row HIT）：

  1. MC 直接發 WRITE 指令（CAS-Write），帶 Column Address + 資料
  2. 資料寫入 Row Buffer 對應的 Sense Amplifier（覆蓋舊值）
  3. Row Buffer 的新值會在 PRE 時寫回 DRAM Cell
情況寫入 gap（pipeline）說明
同 Row（Row HIT）2 CLK直接 CAS-Write，Row Buffer 已開
換 Row（Row MISS）PRE + ACT ≈ 26 CLK先關舊 Row，再開新 Row

Case C  Look Ahead PRE/ACT（非對稱 gap 的成因）

在兩個 Row 之間交替讀取時，MC 會趁著送出資料的空檔，在背景先把下一個 Row 的 PRE 與 ACT 做掉。 結果是同樣是換 Row，兩個方向的 gap 差很多：

5 HBM Switch 與 Reorder

HBM Switch 是什麼

HBM Switch 不是切換 Row 的，它是一個 AXI Crossbar（交叉開關），功能是把多個 AXI Master port 的請求路由到正確的 Memory Controller (MC)。

  你的 FPGA（AXI Master）：

  SAXI_00 ──┐
  SAXI_01 ──┤
  SAXI_02 ──┤                  ┌── MC00 → PC0（addr[31:28]=0）
  SAXI_03 ──┤                  ├── MC01 → PC1
  SAXI_04 ──┤   HBM Switch    ├── MC02 → PC2
  SAXI_05 ──┤   (Crossbar)    ├── MC03 → PC3
  SAXI_06 ──┤   Base Die 上    ├── MC04 → PC4
  SAXI_07 ──┤                  ├── MC05 → PC5
  SAXI_08 ──┤                  ├── MC06 → PC6
  SAXI_09 ──┤                  └── MC07 → PC7
  SAXI_10 ──┤
  SAXI_11 ──┤
  SAXI_12 ──┤
  SAXI_13 ──┤
  SAXI_14 ──┤
  SAXI_15 ──┘

  Switch 的三個功能：
  1. 路由（Route）：  根據 addr[31:28] 決定送到哪個 MC
  2. 仲裁（Arbitrate）：多個 SAXI 同時打同一個 MC 時，決定誰先
  3. Reorder（重排）：同一 SAXI port 的多筆 AR 請求，可以打亂執行順序

ARID 與 Reorder 機制

術語：ARID = AXI Read ID。AXI 規範規定：相同 ARID 的交易必須保持原始順序（in-order），但不同 ARID 之間可以亂序執行。Switch 利用這個規則做 Row 層級的批次重排。

  理想情況（ARID 交替，足夠 queue depth）：

  送進 Switch 的 AR 順序：
    AR[0] ARID=0 → Row0
    AR[1] ARID=1 → Row1
    AR[2] ARID=0 → Row0
    AR[3] ARID=1 → Row1
    AR[4] ARID=0 → Row0
    AR[5] ARID=1 → Row1

  Switch 看到 ARID 0,1,0,1,0,1 → 重排成 Row-Grouped：
    AR[0] ARID=0 → Row0   ←┐ 批次處理
    AR[2] ARID=0 → Row0   ←┘ gap = 2 CLK each
    [一次 Row Switch，~22 CLK]
    AR[1] ARID=1 → Row1   ←┐ 批次處理
    AR[3] ARID=1 → Row1   ←┤ gap = 2 CLK each
    AR[5] ARID=1 → Row1   ←┘
    結果回傳時：ARID=0 按 AR[0],AR[2] 順序；ARID=1 按 AR[1],AR[3],AR[5] 順序

  沒有重排（全 ARID=0）：
    Switch 必須按 AR[0],AR[1],AR[2]... 嚴格順序執行
    每次都要 Row Switch：gap = 16~22 CLK

7 Refresh 機制

為什麼需要 Refresh

DRAM Cell 用電容儲存資料，電容會隨時間自然漏電：

  • 邏輯 1（充滿電） → 電荷慢慢洩漏 → 電壓下降 → 最終 Sense Amplifier 讀不出來
  • 如果超過保留時間（Retention Time）沒有 Refresh → 資料損壞
  電容電壓隨時間下降（示意）：

  Vdd ─── ●  ← 充滿（正確值 = 1）
           │╲
           │  ╲  漏電
           │    ╲
  Vdd/2 ──│──────●────────── ← Sense Amp 判斷門檻（無法辨別 0/1）
           │        ╲
  GND  ────│──────────●──── ← 資料已損壞！

           │← tRETENTION →│
           （HBM2 @85°C ≈ 32 ms）
           （HBM2 @45°C ≈ 64 ms，溫度越低漏越慢）

  解法：在電壓掉到 Vdd/2 之前，強制讀一次再寫回 → Refresh
  HBM2 規格：每 3.9 µs（tREFI）就要做一次 Refresh
Refresh 的本質
Refresh = 強制 ACT（把 row 複製到 row buffer，SA 自動補電） + 然後 PRE（寫回 cell）。 換句話說，Refresh 就是「把所有 row 輪流讀一遍、寫回一遍」，讓電容重新充飽。

tREFI / tRFC 參數詳解

參數全名HBM2 典型值AXI CLK（@450 MHz）說明
tREFI Refresh Interval 3.9 µs ≈ 1755 CLK 兩次 Refresh 之間的最大間隔。MC 必須在這段時間內完成一次 Refresh。
tRFC Refresh Cycle Time ≈ 220 ns ≈ 99 CLK 發出 Refresh 指令後，bank 不可用的時間。Refresh 執行中不能 ACT / CAS / PRE。
tRFCmin Minimum RFC ≈ 160 ns ≈ 72 CLK Single Bank Refresh 的 tRFC（只刷一個 bank，時間較短）。
tREFIpb Per-Bank Refresh Interval ≈ 244 ns ≈ 110 CLK Per-Bank Refresh 模式下每個 bank 的刷新間隔（= tREFI / 16 banks）。 
  Refresh 節奏（All-Bank Refresh，預設模式）：

  時間軸（每格 ≈ 500 CLK）：
  ──────────────────────────────────────────────────────────────────
  │ 正常存取 │ 正常存取 │ 正常存取 │[REF ~99CLK]│ 正常存取 │ ...
  ──────────────────────────────────────────────────────────────────
  ←──────────── tREFI ≈ 1755 CLK ───────────────→

  一次 tREFI（1755 CLK = 3.9 µs）內，有 99 CLK（= 5.6%）不能存取。
  換算：HBM 的 Refresh overhead ≈ 99 / 1755 ≈ 5.6%

Refresh 對 Latency 的影響

Refresh 最痛的地方不是 overhead 比例，而是它會隨機插入並阻擋你的存取請求：

  情況 A：AR 正好在 Refresh 空窗期發出（最幸運）

  AR ──→  [ACT 54 CLK] ──→ [R 資料] ← First Latency = 54 CLK ✅

  ─────────────────────────────────────────────────────────────────
  情況 B：AR 在 Refresh 開始後才到達（最倒楣）

         [REF 99 CLK 進行中，MC 卡住]
  AR ──→ ........等 Refresh 結束........ [ACT] [R 資料]
                                        ↑ 額外等 99 CLK ← Cold MISS (83 CLK情境)

  First Latency ≈ 54 + (部分 tRFC) + tRCDRD
                ≈ 最壞 54 + 99 ≈ 153 CLK（≈ 340 ns）

  ─────────────────────────────────────────────────────────────────
  情況 C：AR 在 Refresh 後到達，但 row buffer 被 PRE 關掉了

  [REF → 自動 PRE 所有 row] ── AR ──→ [ACT 重開 row] [R 資料]
                                      ↑ +tRCDRD = Warm MISS = 67 CLK

三種 First Latency 狀態的完整解釋（含 Refresh）

First Latency條件Refresh 的角色
54 CLK：Row HIT 寫入後 row buffer 仍 open，Refresh 尚未到來 Refresh 還沒打斷，直接 CAS
67 CLK：Warm MISS Refresh 發生並把 row buffer PRE 掉；或 Auto-Precharge 關了 row Refresh 的 REF 指令附帶 PRE → row buffer 清空 → 需重新 ACT（+13 CLK）
83 CLK：Cold MISS AR 剛好在 Refresh 結束後緊接著發出，且還要等 PRE→ACT 還要額外等 tRFC 尾段（約 15–30 CLK），再加 tRCDRD
Refresh 是 Latency Jitter 的主要來源
同樣的存取模式，有時 54 CLK 有時 67 CLK 甚至 83 CLK，完全取決於 AR 發出時 Refresh 走到哪裡。 這是 DRAM 系統 latency 無法完全確定的根本原因。

MC 的 Refresh 調度策略

MC 不是到時間就強制插入 Refresh，而是在「空閒時機」見縫插針：

  Opportunistic Refresh（機會式刷新，HBM MC 的做法）：

  理想情況：在 row switch 的 tRP 空檔裡偷做 Refresh

  ──── [CAS] ─── [PRE] ─────────── [ACT] ─── [CAS] ────
                  ↑ tRP 本來要等
                  └── 如果剛好快到 tREFI，MC 插入 REF
                      ──── [PRE + REF（重疊）] ─── [ACT] ───
                      → Refresh 幾乎不額外增加等待時間！

  強制 Refresh（Mandatory，超過 tREFI 期限）：
  不管現在在幹什麼，MC 都要先完成 Refresh 才繼續服務 AR/AW。
  → 這時才會看到 99 CLK 的「硬 block」

  ─────────────────────────────────────────────────────────────
  Queue Age Limit（我們設 0x7F = 127 CLK）：
  一個 AR 在 Reorder Queue 等超過 127 CLK，就算不是 row hit 也強制執行。
  防止：Refresh 一直插隊，某個 AR 永遠輪不到（Starvation）。

AXI 存取注意事項（來自 PG276）

規則 1：地址必須對齊到 32-byte 邊界（addr[4:0] = 0）

HBM 最小執行單位 = 1 burst = 4 beats × 64 bits = 32 bytes。AWADDR/ARADDR 低 5 bits 若非零，MC 必須拆成兩個 HBM 命令。

  ✅ 對齊存取（addr[4:0] = 5'b00000）：
  ┌────────────────────────────────────────────────────────┐
  │ ARADDR = 0x0_0090_0000  → 1 個 HBM Read 命令           │
  │                         → 100% 有效頻寬                │
  └────────────────────────────────────────────────────────┘

  ❌ 未對齊 Read（addr[4:0] ≠ 0）：
  ┌────────────────────────────────────────────────────────┐
  │ ARADDR = 0x0_0090_0010  → 2 個 HBM Read 命令           │
  │                         → MC 合併資料送回 AXI          │
  │                         → 有效頻寬 ≤ 50%               │
  └────────────────────────────────────────────────────────┘

  ❌❌ 未對齊 Write + ECC 開啟（最壞情況）：
  ┌────────────────────────────────────────────────────────┐
  │ → 2 次 Read-Modify-Write (RMW) 操作                    │
  │   ① Read 第一個 32-byte chunk（含要修改的部分）        │
  │   ② Modify（插入新資料）→ Write 回                     │
  │   ③ Read 第二個 32-byte chunk                          │
  │   ④ Modify → Write 回                                  │
  │ → 有效寫入頻寬 ≤ 25%（4 個 HBM op 換 1 個有效 Write）  │
  └────────────────────────────────────────────────────────┘

規則 2：AxSIZE 固定為 0x5（32 bytes），小 WSTRB 代價高

HBM IP 固定 AxSIZE = 3'b101（32 bytes）。小於 32B 的寫入使用 WSTRB mask，但 HBM protocol 仍執行完整 burst，有效頻寬按比例下降：

實際寫入大小WSTRB有效頻寬建議
32 bytes（全）FFFF_FFFF100%✅ 最佳，保持此寬度
16 bytes0000_FFFF50%若能合併，應合併為 32B
8 bytes0000_00FF25%嚴重低效，應避免
1 byte0000_00013.1%極端低效，禁止
PG276 官方建議：最小 AxLEN = 0x1
PG276 明確建議線性存取時 AxLEN ≥ 0x1（即 2 beats = 64 bytes）以獲得更好的性能。我們的設計用 ARLEN=AWLEN=0xF（16 beats = 512 bytes），完全滿足此建議。

規則 3：Write/Read 方向切換（Bus Turnaround）代價

HBM 只有一個電氣介面（共用 DQ bus），Write 和 Read 不能同時進行，切換方向需要等待 bus settle time：

  ✅ 高效模式（最小化 bus turnaround）：
  ─── [WRITE × N bursts] ──── [turnaround] ──── [READ × M bursts] ───
      N, M 越大，turnaround 開銷佔比越小（被稀釋）

  ❌ 低效模式（頻繁切換）：
  ─── [W1]─[turn]─[R1]─[turn]─[W2]─[turn]─[R2]─[turn]─[W3] ───
      每次切換都浪費數個 CLK，實際利用率大幅下降

  ✅ 高效模式（把 Write 與 Read 分成不同階段）：
  Phase 1: ─── [W1]─[W2]─[W3]─[W4] ─── (純 Write)
  Phase 2: ─── [R1]─[R2]─[R3]─[R4] ─── (純 Read)
  兩個 phase 不交疊，bus turnaround 整段只發生一次

為什麼短 pipeline 測不出 Reorder 效果

當存取模式是「送出 AR → 等待 RLAST → 送下一個 AR」時，每次只有 1 個 AR 在系統中，64-entry Queue 幾乎總是只有 1 個 entry，沒有其他請求可以重排。

PG276 的系統設計建議總結
  • 對齊到 32-byte 邊界（addr[4:0]=0）是第一優先，否則頻寬直接砍半
  • 盡量用長 burst（ARLEN/AWLEN=0xF），攤平 First Latency 和 bus turnaround overhead
  • BG Interleave 開啟（預設），讓連續地址自動交替 BG，隱藏 protocol overhead
  • Write/Read 盡量分開時間段，避免頻繁 bus turnaround（replay 場景天然符合）
  • Reorder 需要足夠的 traffic depth 才有效，pipeline single-beat 場景無效
  • 高溫場景：啟用 Temperature Compensation Refresh，防止 tREFI 減半造成頻寬大幅下降
